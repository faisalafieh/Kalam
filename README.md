# Transcription API

Speaker-attributed transcription for recorded hearings and meetings.
Takes an audio file, returns a transcript where every line is labelled with who spoke it.

Pairs with the browser recorder frontend (hosted separately on Netlify).

## What it does

1. Accepts any audio container the browser produces (webm/opus, mp4, wav)
2. Normalises it to 16 kHz mono with ffmpeg
3. Transcribes with faster-whisper
4. Diarizes with pyannote 3.1
5. Assigns each transcript segment to the speaker with the largest time overlap

## API

```
POST /transcribe        multipart/form-data, field "audio"
GET  /health
```

Optional form fields on `/transcribe`:

| Field | Values | Effect |
|---|---|---|
| `language` | `en`, `ar`, `mixed`, `auto` | Spoken language. `mixed` re-detects language on every segment, for Arabic–English code-switching. Default: `LANGUAGE` |
| `dialect` | `auto`, `msa`, `gulf`, `levantine`, `egyptian`, `maghrebi` | Arabic dialect (ignored for English). `auto` guesses it from the opening seconds. Default: `DIALECT` |
| `vocabulary` | comma-separated text, ≤ 500 chars | Names and terms to hint to Whisper throughout: judges, parties, firms, case terms |
| `num_speakers` | 1–20 | Exact speaker count, if known. Big diarization gain |
| `min_speakers`, `max_speakers` | 1–20 | Bounds when the exact count is unknown |

Response:

```json
{
  "segments": [
    {"speaker": "SPEAKER_00", "start": 0.0, "end": 2.4, "text": "You may proceed."},
    {"speaker": "SPEAKER_01", "start": 2.5, "end": 6.1, "text": "Thank you, turning to the exhibit."}
  ],
  "speakers": 2,
  "duration": 61.2,
  "language": "en",
  "dialect": null,
  "dialect_detected": false
}
```

## Arabic and dialects

Whisper has a single `ar` language for every variety of Arabic and leans
towards Modern Standard Arabic, so dialect words tend to get rewritten into MSA
or dropped. Kalam handles this in three ways (code in `arabic.py`):

1. **A bigger model for Arabic.** Small Whisper models are far weaker on Arabic
   than on English. Arabic and mixed requests use `ARABIC_MODEL` (default
   `large-v3`), loaded on the first Arabic request; English keeps `WHISPER_MODEL`.
2. **A dialect primer on every window.** A short sentence written in the chosen
   dialect (Gulf, Levantine, Egyptian, Maghrebi, or MSA court register) is passed
   to Whisper as `hotwords`, which faster-whisper places in front of every 30 s
   window, nudging the whole transcript towards that dialect's spelling and words.
   Caller `vocabulary` is appended, so names and legal terms come out right too.
3. **Automatic dialect choice.** With `dialect=auto`, the first
   `DIALECT_PROBE_SECONDS` are transcribed and scored against marker words typical
   of each dialect (e.g. شلون/وايد for Gulf, هلق/منيح for Levantine,
   دلوقتي/عايز for Egyptian, دابا/بزاف for Maghrebi). This is a heuristic, not a
   trained classifier: it only commits on clear evidence and otherwise uses the
   MSA primer. The response reports which dialect was used.

None of this is a measured accuracy claim. To get one, record speakers of each
dialect, write the references by ear, and score each dialect as its own run:

```bash
LANGUAGE=ar DIALECT=gulf python eval/evaluate.py --manifest eval/data/gulf/manifest.jsonl --tag ar-gulf
LANGUAGE=ar DIALECT=auto python eval/evaluate.py --manifest eval/data/gulf/manifest.jsonl --tag ar-gulf-auto
```

Arabic text is scored with Arabic normalisation (diacritics, alef/ya/ta marbuta
variants, Arabic digits and punctuation unified) instead of Whisper's English
normaliser. Compare a run with the dialect fixed against one with `auto` and one
with `msa` to see what the primer is worth on your recordings.

`large-v3` on CPU is slow (several times real time) and needs roughly 3–4 GB of
RAM alongside pyannote; for Arabic in production a GPU host (Modal, or `DEVICE=cuda`
with `COMPUTE_TYPE=float16`) is the practical option.

## Before it will run

`pyannote/speaker-diarization-3.1` is a gated model. Two steps, both required:

1. Log in to Hugging Face and accept the terms on the model page **and** on `pyannote/segmentation-3.0`
2. Create a read token in Settings → Access Tokens, and set it as `HF_TOKEN`

Without the token the server still starts, but returns transcripts with no speaker labels.

## Run locally

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # add your HF_TOKEN
export $(cat .env | xargs)
uvicorn app:app --reload
```

Needs ffmpeg installed (`brew install ffmpeg`, or `apt install ffmpeg`).

Test it:

```bash
curl -F "audio=@sample.wav" http://localhost:8000/transcribe
```

## Accuracy

Measured results live in [`eval/RESULTS.md`](eval/RESULTS.md), generated by the
evaluation harness in `eval/`. The harness runs the exact production pipeline
(`app.run_pipeline`) and reports three numbers:

| Metric | Question it answers |
|---|---|
| **WER** (word error rate) | Are the words right? |
| **cpWER** (speaker-attributed WER) | Are the words right *and* credited to the right person? |
| **DER** (diarization error rate) | Is the timeline of who spoke when right? |

Text is normalised with Whisper's English normaliser before scoring (case,
punctuation, "3" vs "three", fillers like "um"), which is the convention used in
published ASR benchmarks. Rates are pooled over all reference words, not averaged
per file.

### Public benchmark: AMI Meeting Corpus

Real, unscripted 3–5 person meetings with hand-made transcripts (CC BY 4.0),
official test split, diarization references from
[BUTSpeechFIT/AMI-diarization-setup](https://github.com/BUTSpeechFIT/AMI-diarization-setup).

```bash
pip install -r requirements.txt -r eval/requirements.txt
export HF_TOKEN=...            # needed for speaker labels, see above

python eval/prepare_ami.py                    # 4 meetings (~1.6 h), headset mix
python eval/evaluate.py --manifest eval/data/ami/manifest_headset.jsonl --tag ami-headset

python eval/prepare_ami.py --mic distant      # single table microphone, harder
python eval/evaluate.py --manifest eval/data/ami/manifest_distant.jsonl --tag ami-distant
```

Add `--all` to `prepare_ami.py` for all 16 test meetings (~9 h of audio).

Compare settings on the development meetings (`--split dev`) and run the test
set once with the configuration chosen there; picking settings by their test
score overstates accuracy.

### On a GPU (Google Colab)

Large Whisper models are slow on a laptop CPU. `eval/kalam_colab.ipynb` runs the
whole protocol on a free Colab T4: compares the original configuration, small, large-v3-turbo and large-v3, with and without speech separation
(plus a word- vs segment-level speaker ablation) on the dev meetings, picks the
best by dev cpWER, then runs the full test set once with both the original and the selected configuration.
[Open in Colab](https://colab.research.google.com/github/faisalafieh/kalam/blob/main/eval/kalam_colab.ipynb)
(for a private repo, upload the notebook to Colab instead).

### Your own recordings

Put audio and a hand-checked transcript side by side and list them in a
`manifest.jsonl` (see the docstring in `eval/evaluate.py`). The transcript is
plain text, one line per turn:

```
Judge: You may proceed.
Counsel: Thank you. Turning to exhibit three.
```

Write the reference by listening to the audio, not by correcting Kalam's own
output; a corrected machine transcript inherits its mistakes and inflates the
score. Everything under `eval/data/` and cached transcripts under
`eval/results/hyp/` are git-ignored, so private recordings stay local.

## Deploy

Any host that runs a Dockerfile works. Memory is the binding constraint:
whisper-small plus pyannote needs roughly 2 GB, so a 512 MB free tier will
be killed mid-request.

| Host | Notes |
|---|---|
| Hugging Face Spaces | **Free** (2 CPU, 16 GB RAM). `.github/workflows/deploy-space.yml` deploys on every push to main once the `HF_TOKEN` repo secret is set; setup steps are at the top of that file. Sleeps when idle, slow on CPU. |
| Render | Docker runtime, `render.yaml` included. Free tier too small for diarization; the paid starter instance fits. |
| Modal | Serverless, charges per second of execution, free monthly credits. Best fit if the model needs a GPU. |
| Fly.io | Scale-to-zero, small always-free allowance. |

Set `ALLOWED_ORIGINS` to your frontend's exact URL once deployed, otherwise
the browser will block the upload.

## Configuration

| Variable | Default | Purpose |
|---|---|---|
| `HF_TOKEN` | — | Hugging Face token, required for diarization |
| `WHISPER_MODEL` | `small` | `tiny` and `base` are much faster on CPU and much less accurate |
| `LANGUAGE` | `en` | Default spoken language: `en`, `ar`, `mixed` (Arabic–English code-switching) or `auto` (unreliable with accented speakers) |
| `DIALECT` | `auto` | Default Arabic dialect: `auto`, `msa`, `gulf`, `levantine`, `egyptian`, `maghrebi` |
| `ARABIC_MODEL` | `large-v3` | Whisper model for Arabic and mixed requests |
| `PRELOAD_ARABIC` | `false` | Load `ARABIC_MODEL` at startup instead of on the first Arabic request |
| `DIALECT_PROBE_SECONDS` | `90` | Audio transcribed to guess the dialect when `dialect=auto` |
| `VOCABULARY` | — | Comma-separated names/terms always hinted to Whisper |
| `AUDIO_FILTER` | — | ffmpeg filter applied on conversion, e.g. `highpass=f=80,loudnorm` for quiet distant speakers. Test on dev data first |
| `HALLUCINATION_SILENCE` | `0` | Seconds; skip long silences where Whisper appears to hallucinate (needs word-level speakers). `0` = off |
| `BEAM_SIZE` | `5` | Beam search width; `1` is faster but drops more speech |
| `CONDITION_ON_PREVIOUS` | `false` | Feed each window the previous text; `true` can cause repetition loops on long audio |
| `SEPARATE` | `false` | Separate overlapping speakers into one stream each before transcribing (needs `pyannote.audio[separation]`, a GPU, and accepted terms on `pyannote/speech-separation-ami-1.0`) |
| `WORD_SPEAKERS` | `true` | Assign speakers per word (Whisper word timestamps) rather than per segment |
| `DIARIZE` | `true` | Set `false` to return transcripts without speaker labels |
| `DEVICE` | `cpu` | `cuda` when a GPU is available |
| `COMPUTE_TYPE` | `int8` | `float16` on GPU |
| `ALLOWED_ORIGINS` | `*` | Comma-separated list of allowed frontend origins |
| `MAX_MB` | `200` | Rejects uploads larger than this |

## Handling of audio

Uploads are written to a temporary directory and deleted when the request
finishes, whether it succeeded or not. Nothing is written to a database or
retained between requests.
